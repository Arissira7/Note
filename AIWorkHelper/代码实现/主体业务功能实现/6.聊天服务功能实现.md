## 2.4 websocket方法定义

要完成上述说的聊天功能，需要给websocket server的对象添加如下五个方法

|方法 |释义 |
|---|---|
|send |发送消息 |
|addConn |用户登陆新建链接 |
|closeConn |关闭连接 |
|handleConn |处理连接的用户 |
|auth |对登陆的用户鉴权 |

明确了连接处理函数之后，首先我们要用一个集合把这些连接给管理起来，这里我们可以用map来存储用户和连接的映射关系，用两个map来存储，uidToConn和connToUid，分别存储用户到连接的映射和连接到用户的映射。在Ws对象中添加这两个map

```go
type Ws struct {
    websocket.Upgrader
    svc         *svc.ServiceContext
    uidToConn map[string]*websocket.Conn
    ConnToUid map[*websocket.Conn]string
}
```

### 2.4.1 addConn方法定义

添加连接的实现很简单，连接不存在的话，就在uidToConn中添加一条记录，连接存在的话，就把之前的连接关闭掉，重新连接。但是这里涉及到对于map的插入操作，多个用户可能存在并发安全问题，所以可以加一个读写锁，所以先在Ws加入一个读写锁

```go
type Ws struct {
    websocket.Upgrader
    svc         *svc.ServiceContext
    uidToConn map[string]*websocket.Conn
    ConnToUid map[*websocket.Conn]string
    
    sync.RWMutex
}
```

然后就可以在/internal/domain/ws.go文件中实现addConn方法了

```go
func (s *Ws) addConn(conn *websocket.Conn, uid string) {
    s.RWMutex.Lock()
    defer s.RWMutex.Unlock()

    if c := s.uidToConn[uid]; c != nil {
       c.Close()
    }

    s.uidToConn[uid] = conn
    s.ConnToUid[conn] = uid
}
```

### 2.4.2 closeConn方法定义

关闭连接的实现很简单，只需要根据连接对象来操作即可，先从ConnToUid去除用户ID，将这一组用户和连接的映射从uidToConn和ConnToUid两个map中删除，最后在关闭连接即可

```go
// closeConn 关闭连接
func (s *Ws) closeConn(conn *websocket.Conn) {
    s.RWMutex.Lock()
    defer s.RWMutex.Unlock()

    uid := s.ConnToUid[conn]
    if uid == "" {
       return
    }

    fmt.Printf("关闭 %s 连接\n", uid)

    delete(s.ConnToUid, conn)
    delete(s.uidToConn, uid)

    conn.Close()
}
```

### 2.4.3 send方法定义

发送消息方法这里需要实现两个，一个是根据连接放消息，一个是根据用户id发送消息，即向某个用户发送消息。一般情况下从业务层面上来分析，都是基于用户去发送消息的，但是底层实现上其实是基于连接发送消息，为了方便后续扩展，所以这里把基于连接发送消息也做一个实现

1. 基于连接发送消息

```go
func (s *Ws) send(ctx context.Context, conn *websocket.Conn, v interface{}) error {
    b, err := json.Marshal(v)
    if err != nil {
       tlog.ErrorCtx(ctx, "conn.send", err.Error())
       return err
    }

    return conn.WriteMessage(websocket.TextMessage, b)
}
```

- 基于用户id发送消息

向用户id发送消息的时候，这里有可能是单聊，也有可能是群聊，向一群用户发消息，所以这里的用户id我们可以选择用可变参数来实现

```go
// 向用户id发送消息
func (s *Ws) sendByUids(ctx context.Context, msg interface{}, uids ...string) error {
    s.RWMutex.RLock()
    defer s.RWMutex.RUnlock()

    if len(uids) == 0 {
       for i, _ := range s.uidToConn {
          if err := s.send(ctx, s.uidToConn[i], msg); err != nil {
             tlog.ErrorCtx(ctx, "sendByUids.all.send", err.Error())
             return err
          }
       }
    }

    for _, uid := range uids {
       c, ok := s.uidToConn[uid]
       if !ok {
          continue
       }
       if err := s.send(ctx, c, msg); err != nil {
          tlog.ErrorfCtx(ctx, "sendByUids.one.send err %v, uid %v", err.Error(), uid)
          return err
       }
    }
    return nil
}
```

从实现上可以看出，起底层真正的发送动作还是用的前面的机遇连接的发送方法来实现的

```go
func (s *Ws) auth(r *http.Request) (uid string, tokenStr string, err error) {
    tok := r.Header.Get("sec-websocket-protocol")
    if tok == "" {
       return "", "", errors.New("没有登入，不存在访问权限")
    }

    claims, tokenStr, err := s.tokenparser.ParseToken(tok)
    if err != nil {
       return "", "", err
    }

    return claims[token.Identify].(string), tokenStr, nil
}
```

### 2.4.5 handleConn方法实现

handleConn方法的实现需要依赖于ServeWs方法，需要将接受的到的用户请求升级为websocket的时候才处理。所以，这里我们首先完成ServerWs方法

```go
func (s *Ws) ServerWs(w http.ResponseWriter, r *http.Request) {
    defer func() {
       if e := recover(); e != nil {
          tlog.ErrorCtx(r.Context(), "serverWs", e)
       }
    }()

    // 鉴权
    uid, token, err := s.auth(r)
    if err != nil {
       tlog.ErrorfCtx(r.Context(), "serverWs", "auth fail %v", err.Error())
       return
    }

    // 请求升级
    respHeader := http.Header{
       "websocket": []string{token},
    }
    c, err := s.Upgrade(w, r, respHeader)
    if err != nil {
       tlog.ErrorfCtx(r.Context(), "serverWs", "Upgrade fail %v", err.Error())
       return
    }

    // 记录连接
    s.addConn(c, uid)

    go s.handleConn(c, uid, token)
}
```

```go
func (s *Ws) handlerConn(conn *websocket.Conn, uid, tok string) {
    for {
       // 接收请求
       _, msg, err := conn.ReadMessage()
       if err != nil {
          tlog.Errorf("serverWs", "conn.ReadMessage fail %v, uid %v", err.Error(), uid)
          s.closeConn(conn)
          return
       }

       ctx := s.context(uid, tok)

       var req domain.Message
       if err := json.Unmarshal(msg, &req); err != nil {
          tlog.ErrorfCtx(ctx, "handlerConn", "json.Unmarshal fail %v", err.Error())
          return
       }
       req.SendId = uid
       // 分发请求
       switch model.ChatType(req.ChatType) {
       case model.SingleChatType:
          err = s.privateChat(ctx, conn, &req)
       case model.GroupChatType:
          err = s.groupChat(ctx, conn, &req)
       }

       if err != nil {
          tlog.ErrorfCtx(ctx, "handlerConn", "message handle fail %v, msg %v", err.Error(), req)
          return
       }
    }
}
```

这里还有两个方法需要实现，在分发请求的时候，需要进行私聊和群聊的处理，在/internal/handler/ws/conversation.go文件中完成私聊和群聊的方法定义

```go
func (s *Ws) privateChat(ctx context.Context, conn *websocket.Conn, req *domain.Message) error {
    if err := s.chat.PrivateChat(ctx, req); err != nil {
       return err
    }

    return s.sendByUids(ctx, req, req.RecvId)
}

func (s *Ws) groupChat(ctx context.Context, conn *websocket.Conn, req *domain.Message) error {
    if _, err := s.chat.GroupChat(ctx, req); err != nil {
       return err
    }

    return s.sendByUids(ctx, req)
}
```
