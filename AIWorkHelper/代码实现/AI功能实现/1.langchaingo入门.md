# LangChainGo入门

LangChain 是一个用于开发由大型语言模型提供支持的应用程序的框架 （LLMs）。旨在帮助开发人员使用语言模型构建端到端的应用程序。它提供了一套工具、组件和接口，可简化创建由大型语言模型 (LLM) 和聊天模型提供支持的应用程序的过程。LangChain 可以轻松管理与语言模型的交互，将多个组件链接在一起，并集成额外的资源，比如API，数据库等等。

目前LangChain提供了 Python 和TypeScript的软件包。langchain官网地址：https://www.langchain.com/

LangChainGo可以理解为LangChain 框架的 Go 语言版本框架地址：https://github.com/tmc/langchaingo

这篇文档只是对LangChain框架以及框架里的核心组件做一个简单的介绍，具体的框架细节以及使用方法大家可以去上面两个连接地址学习

# 2. 为什么要用 LangChain

* **智能数据整合：**&#x4C;angchain框架支持将大规模语言模型与多样化数据存储系统进行深度对接，包括结构化数据库、非结构化PDF文档及其他文件格式。该特性使得企业能够充分挖掘私有知识库中的潜在价值，通过语义解析实现精准信息抽取。

* **操作自动化扩展：**&#x4C;angchain不仅可以提取信息，还可以根据这些信息执行特定的操作，比如可以自动化发送邮件。其核心优势在于采用动态参数化编程范式，避免硬编码，显著提升系统可维护性和扩展性。

## 6.2 Memory模块

LangChain的Memory模块是构建真正对话式AI应用的核心组件之一。它使得大型语言模型（LLM）不再仅仅是一个无状态的、一次性回答问题的工具，而是能够“记住”之前的交互，从而进行有上下文的、连贯的对话。

在默认情况下，LLM本身是无状态的。这意味着对于每一个新的输入，它都会独立地进行处理，而不会记得之前的任何信息。例如，如果你先问“我叫张三”，再问“我叫什么名字？”，一个没有记忆功能的模型将无法回答第二个问题。

Memory模块的出现正是为了解决这个问题。它提供了一种机制，用于存储、管理和利用过去的对话信息，并将其作为上下文注入到未来的模型调用中，从而实现连贯的对话体验。

### 6.2.1 Memory模块的核心工作原理

LangChain中的Memory模块主要负责两个核心操作：

1. **读取（Read）**: 在将新的用户输入发送给LLM之前，从内存中读取历史对话信息，并将其与当前输入一起作为上下文提供给模型。

2. **写入（Write）**: 在LLM生成响应之后，将当前的输入和输出写入到内存中，以备将来的对话使用。

这些历史信息可以以多种形式存在，例如完整的对话记录、摘要、或者结构化的知识图谱。

# 7. Agent模块

&#x20;Agent 是一个能够**利用大型语言模型（LLM）作为其“大脑”**，进行**自主思考、推理和决策**的程序。

与简单的直接调用 LLM 获取答案不同，Agent 具备以下关键能力：

1. **动态决策 (Dynamic Decision Making)**: Agent 能够根据用户的输入和当前情况，决定下一步应该执行什么操作。它不是遵循一个固定的、预先编程好的逻辑流程。

2. **工具使用 (Tool Using)**: 这是 Agent 的核心。它可以访问并使用一系列预先定义的“工具”（Tools）。这些工具可以是任何东西：搜索引擎、数据库查询、API 调用、计算器，甚至是另一个 Chain。

3. **观察与迭代 (Observation and Iteration)**: Agent 执行一个动作（使用工具）后，会“观察”这个动作产生的结果，然后基于这个新结果再次进行思考和决策，直到最终找到用户问题的答案或完成指定的任务。

Agent的思想是一种“推理+行动”的思想，也就是遵循我们说的react理论

![](<images/1. LangChainGo入门-6.png>)

当 Executor 接收到用户输入后，它会启动以下循环：

1. **Prompt 组装**: Executor 会将用户的**问题 (Question)**、可用的**工具描述 (Tool Descriptions)**、以及之前的**思考和行动历史 (Scratchpad)** 组合成一个复杂的 Prompt。

2. **LLM 推理**: 将这个 Prompt 发送给 LLM。LLM 的任务是输出一段包含特定格式的文本，这段文本包含了它的**思考 (Thought)** 和下一步的**行动 (Action)**。

   * **Thought**: “我需要找到 LangChainGo 的 GitHub 仓库地址。”

   * **Action**: `Search("LangChainGo github")` (这里 `Search` 是工具名，括号内是输入)

3. **行动解析与执行**: Executor 解析出 LLM 指定的 `Action`，找到对应的工具（`Search` 工具）并执行它，传入参数 `"LangChainGo github"`。

4. **观察结果 (Observation)**: 工具执行后会返回一个结果，例如搜索结果的摘要。这个结果被称为 `Observation`。

5. **更新历史**: Executor 将上一步的 `Action` 和这一步的 `Observation` 追加到 `Scratchpad` 中。

6. **循环/结束**: Executor 检查任务是否完成。

   * 如果 LLM 在某一步的输出中包含了**最终答案 (Final Answer)**，则循环结束，将答案返回给用户。

   * 如果任务未完成，则回到第一步，带着更新后的 `Scratchpad` 开始新一轮的思考和行动。
