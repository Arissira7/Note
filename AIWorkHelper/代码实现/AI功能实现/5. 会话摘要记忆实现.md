# 1. summary简介

summary机制其实是memory实现的一种，我们知道memory机制是使大模型具有记忆能力的关键。通常的实现就是把之前的会话记录在本次会话一并传递给大模型。这样大模型就能够清楚我们之前的历史聊天信息，可以将历史聊天信息作为上下文，回答问题就更准确，但是将所有的历史记录每次都传递给大模型的话，这个token的消耗是非常大的，所以就有了我们下面的summary机制

简单来说summary机制就是每次和大模型对话，都会对这次对话做一个总结，然后总结完之后将这个信息保存起来，然后在下一次对话的时候，会把这次总结作为聊天记录一起传递个大模型，起到一个上下文记忆的作用，因为是对历史会话的总结，所以这里的token就会小很多。一个简单的summary流程如下图所示：

这里summary实现之后，还要在DefaultHandler中添加一个记忆机制

在`/internal/logic/chatinternal/prompts.go`添加如下代码

```go
package chatinternal

const (
    // BASE_PROMPAT_TEMPLATE 对话历史模板
    BASE_PROMPAT_TEMPLATE = `Current conversation:
{{.history}}\n\n`

    // OUT_PROMPT_TEMPLATE 输出格式模板，定义AI响应的JSON结构
    OUT_PROMPT_TEMPLATE = `<< instructions >>
- Your response should follow the JSON format.
- Your response should have the following structure: {"chatType": {{.chatType}}, "data": {{.data}} }
- "chatType" this is a fixed output`
)
```

在`/internal/logic/chatinternal/emptyhandle.go`中的NewDefaultHandler的提示词模板中添加记忆机制

```go
// NewDefaultHandler 创建默认聊天处理器
func NewDefaultHandler(svc *svc.ServiceContext) *DefaultHandler {
    // 定义AI助手的基础提示词
    template := "you are an all-round assistant, please help me answer this question: \n\n<< input >>\n{{.input}}"

    // 构建提示词模板
    prompt := prompts.PromptTemplate{
       Template:       Template:       BASE_PROMPAT_TEMPLATE + template + "\n\n" + OUT_PROMPT_TEMPLATE,
       InputVariables: []string{langchain.Input},
       TemplateFormat: prompts.TemplateFormatGoTemplate,
       PartialVariables: map[string]any{
          "chatType": fmt.Sprintf("%d", domain.DefaultHandler),
          "data":     "solution",
       },
    }

    return &DefaultHandler{
       svc: svc,
       c:   chains.NewLLMChain(svc.LLMs, prompt, chains.WithCallback(svc.Callbacks)),
    }
}
```

# 4. summary\_buf实现

前面分析的summary机制其实是每次都会对会话做一个总结，这个其实对于我们当前业务模型来说并不是那么合适，有时候如果会话本身内容就很少，大模型也会帮我们总结，这个时候反而消耗的token更多。所以我们这里做一个优化，来实现一个summary\_buf机制。

![](<images/5. 会话摘要记忆实现-summary_buff.png>)

summary\_buf的整体逻辑如上图所示，大模型不会对我们的每一次会话做总结，而是当我们的会话的token数量擦后错一定的阈值的时候再做总结，如果没超过，就用原内容即可。这样的话既有会话的记忆功能，也对会话的token消耗做了一定的优化

summary\_buf的实现在`/pkg/langchain/memoryx/summarybuff.go`文件中来实现。内容表多，直接配合看源码就可以了
