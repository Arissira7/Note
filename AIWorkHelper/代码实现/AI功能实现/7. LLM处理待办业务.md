在上一节中我们已经分析了AI助手如何调用主体业务，在本节内容中我们将分析llms如何实现待办事项的处理。

# 1. 业务分析&#x20;

关于AI助手中对于待办我们将主要为如下业务:

* 待办的创建

* 待办的查询

关于删除和修改这两项不是很推荐直接通过 AI 处理，修改是需要根据具体信息修改，而删除则最好以依据用户的用户手动操作为准; 因为 AI 在目前的一些常见的模型中实际上仍然是存在着不稳定的情况，因此通过 AI 调用删除和修改则可能会造成不正确的结果。 在流程中

1. 用户发送消息：“创建一个待办，明天下午3点开服，项目计划讨论会议”

2. AI 根据消息，那么理应需要去创建待办

3. 当待办创建后，AI 可直接返回或者查询该次待办信息。

# 2. 流程分析&#x20;

结合前面的内容分析我们需要定义一个 todohandle 用于处理待办相关的事情，再定义待办的 todo 处理具体任务。 而在课程的内容中我们已经分析了 aichat 将通过 curl 调用到主题的业务，通过这样的方式来完成项目 的待办事项。 因此具体情况则如下图:

## 3.1 **问题分析**

前面已经分析了实现的大致流程，但实际上还存在一个新的问题需要解决，**todo 业务所需字段的定义问题**。

根据之前课程学习，我们可以通过 **`outputparser` 中的 `structured`** 来描述所需字段，告诉大模型返回的结果应该是什么样子。但是，这里存在一个限制：

* 直接使用 `structured` 对象时，默认所有字段的属性类型都是 **string**，

* **不支持自定义类型的扩展**。

相关代码文件路径：/tmc/langchaingo/outputparser/structured.go

```go
func (p Structured) GetFormatInstructions() string {
    jsonLines := ""
    for _, rs := range p.ResponseSchemas {
        jsonLines += "\t" + fmt.Sprintf(
            _structuredLineTemplate,
            rs.Name,
            "string", /* type of the filed */
            rs.Description,
        )
    }
    return fmt.Sprintf(_structuredFormatInstructionTemplate, jsonLines)
}
```

实际todo的添加查询接口的参数为如下，在字段中显然不止string，还有如：int、int64等

```go
type (
    Todo {
        CreatorId   string `json:"creatorId,omitempty"`
        CreatorName string `json:"creatorName,omitempty"`
        Title       string `json:"title,omitempty"`
        DeadlineAt  int64  `json:"deadlineAt,omitempty"`
        Desc        string `json:"desc,omitempty"`
        Status      int    `json:"status,omitempty"`
    }

    todoListReq {
        Id        string `json:"id,omitempty"`
        UserId    string `json:"userId,omitempty"`
        Page      int    `json:"page,omitempty"`
        Count     int    `json:"count,omitempty"`
        StartTime int64  `json:"startTime,omitempty"`
        EndTime   int64  `json:"endTime,omitempty"`
    }
)

```

所以需要我们自己去封装这个接口参数

* 构建toolx

代码中我们在/internal/logic/internal/logic/chatinternal下新建一个toolx目录，在toolx目录去实现AI待办功能，根据前面的分析，AI待办主要有创建待办和查询待办。所以在toolx目录下新建两个文件：todoadd.go和todofind.go

todoadd.go

```go
package toolx

import (
    "AIWorkHelper/internal/svc"
    "AIWorkHelper/pkg/curl"
    "AIWorkHelper/pkg/langchain/outputparserx"
    "AIWorkHelper/pkg/token"
    "context"
    "fmt"
    "github.com/tmc/langchaingo/callbacks"
)

type TodoAdd struct {
    svc          *svc.ServiceContext
    callback     callbacks.Handler
    outPutParser outputparserx.Structured
}

func NewTodoAdd(svc *svc.ServiceContext) *TodoAdd {
    return &TodoAdd{
       svc:      svc,
       callback: svc.Callbacks,
       outPutParser: outputparserx.NewStructured([]outputparserx.ResponseSchema{
          {
             Name:        "title",
             Description: "todo title",
          }, {
             Name:        "deadlineAt",
             Description: "calculate the final deadline based on the time information entered by the user and combined with today's time. a Unix time",
             Type:        "int64",
          }, {
             Name:        "desc",
             Description: "todo description",
          }, {
             Name:        "executeIds",
             Description: "list of participating users in the backlog. the data type is a set of string ids. none is empty",
             Type:        "[]string",
          },
       }),
    }
}

func (t *TodoAdd) Name() string {
    return "todo_add"
}

func (t *TodoAdd) Description() string {
    template := `a todo add interface.
use when you need to create a todo.
keep Chinese output.` + t.outPutParser.GetFormatInstructions() // 保持中文输出

    return template
}

func (t *TodoAdd) Call(ctx context.Context, input string) (string, error) {
    if t.callback != nil {
       t.callback.HandleText(ctx, "todo add start : "+input)
    }

    data, err := t.outPutParser.Parse(input)
    if err != nil {
       return "", err
    }

    res, err := curl.PostRequest(token.GetTokenStr(ctx), t.svc.Config.Host+"/v1/todo", data)

    if err != nil {
       return "", err
    }

    fmt.Println(res)
    return "success", nil

}
```
