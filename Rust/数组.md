## Rust 里"数组/序列"家族

| 类型                                 | 分配位置       | 大小是否编译期可知 | 典型用途                               |
| ---------------------------------- | ---------- | --------- | ---------------------------------- |
| `[T; N]`                           | 栈（嵌入外层结构体） | 是         | 长度固定的缓冲区、SIMD、const fn             |
| `[T]`（unsized）                     | 不可独立存在     | 否（DST）    | 必须放在 `&[T]`、`Box<[T]>`、`Vec<T>` 后面 |
| `&[T]` / `&mut [T]`                | 胖指针        | 否         | 借用一段连续元素，没有所有权                     |
| `Box<[T]>`                         | 堆          | 长度运行时定    | 拥有所有权、长度不再变化（不可 push）              |
| `Vec<T>`                           | 堆          | 否         | 你现在用的，长度可变                         |
| `VecDeque<T>`                      | 环形堆        | 否         | 双端 O(1)，适合作队列                      |
| `SmallVec<T>` / `ArrayVec<T>`（第三方） | 先栈后堆 / 仅栈  | 一般是       | 小尺寸优化，避免堆分配                        |
| `String`                           | 堆          | 否         | 等价于 `Vec<u8>` + UTF-8 不变量          |
| `bytes::Bytes` / `BytesMut`        | 堆（引用计数）    | 否         | 网络/IO 里零拷贝切片                       |

Rust 的“数组/序列”家族确实非常庞大，这是因为 Rust 赋予了开发者对内存极其精细的控制权。要彻底理解它们，最好的方式就是直接看它们在**栈（Stack）**和**堆（Heap）**上的内存布局。

这里我将为你逐一拆解这些类型的底层本质，并配以内存布局图和使用示例。

### 1. `[T; N]` (固定大小数组)

这是最基础的数组，它的大小在编译期就已确定，**所有元素连续地分配在栈上**（或者直接嵌入在包含它的结构体/堆分配对象中）。没有额外的指针或长度开销。

```text
栈 (Stack)
+-------+-------+-------+
| arr[0]| arr[1]| arr[2]| (连续的 3 个 i32，共 12 字节)
+-------+-------+-------+
```

- **底层本质**：纯粹的连续数据块，零额外开销。
    
- **如何使用**：
    
    ```rust
    // 编译期确定长度为 3，分配在栈上
    let arr: [i32; 3] = [1, 2, 3];
    ```
    

### 2. `[T]` (Unsized Slice，动态大小类型)

`[T]` 并不是一个你可以直接持有的类型（它是动态大小类型 DST，Dynamically Sized Type）。它代表着**“内存中的一段连续元素”**，但在编译期不知道它有多长。因此，你无法在栈上为它分配空间，它永远只能躲在指针后面（例如 `&[T]`、`Box<[T]>`）。

- **底层本质**：一片纯粹的数据序列，缺乏描述自身的元数据（指针和长度）。
    
- **如何使用**：不能单独使用，编译器会报错。
    

### 3. `&[T]` / `&mut [T]` (切片引用 / 胖指针)

这是 Rust 中最常用的“借用视图”。它是一个**胖指针（Fat Pointer）**，由两个机器字（Word）组成，分配在栈上。它指向某段已经存在的内存（可能是栈、堆，或者静态内存段）。

```text
栈 (Stack)                       内存中某处 (栈/堆/静态区)
+----------------+             +-------+-------+-------+
| ptr (数据指针) | ----------> | val_1 | val_2 | val_3 | ...
+----------------+             +-------+-------+-------+
| len (长度: 3)  |
+----------------+
```

- **底层本质**：`指针 + 长度`。它不拥有数据（没有所有权），只提供一个窗口。
    
- **如何使用**：
    
    ```rust
    let arr = [1, 2, 3, 4, 5];
    // slice 是一个 &[i32]，指向 arr 的第 1 到 3 个元素
    let slice: &[i32] = &arr[1..4]; 
    ```
    

### 4. `Box<[T]>` (堆上拥有的固定长度切片)

当你需要拥有数据的所有权，并且希望把它放在堆上，但**不需要它动态增长**时使用。它的栈上结构与 `&[T]` 完全一样（也是胖指针），但区别在于它拥有堆上数据的**所有权**，负责其生命周期的清理。

```text
栈 (Stack)                       堆 (Heap - 拥有所有权)
+----------------+             +-------+-------+-------+
| ptr (数据指针) | ----------> | val_1 | val_2 | val_3 |
+----------------+             +-------+-------+-------+
| len (长度: 3)  |
+----------------+
```

- **底层本质**：堆分配的精确大小的切片，不能 `push` 或 `pop`，节省了 `Vec` 的 `capacity` 字段（省了一个机器字的内存）。
    
- **如何使用**：
    
    ```rust
    // 通常由 Vec 转换而来，释放多余的 capacity
    let boxed_slice: Box<[i32]> = vec![1, 2, 3].into_boxed_slice();
    ```

你最常用的动态数组。它分配在堆上，并且可以动态扩容。在栈上，它由三个机器字组成：数据指针、当前长度（已使用）、总容量（已分配空间）。

```text
栈 (Stack)                       堆 (Heap - 拥有所有权)
+----------------+             +-------+-------+-------+-------+-------+
| ptr (数据指针) | ----------> | val_1 | val_2 | val_3 | 未初始化的内存|
+----------------+             +-------+-------+-------+-------+-------+
| len (长度: 3)  |
+----------------+
| cap (容量: 5)  |
+----------------+
```

- **底层本质**：`指针 + 长度 + 容量`。当 `len == cap` 时再插入数据，会自动申请一块更大的内存，把旧数据拷过去，释放旧内存。
    
- **如何使用**：
    
    ```rust
    let mut v = Vec::with_capacity(5);
    v.push(1); // 动态增长
    ```

`Vec` 只能在尾部高效插入（O(1)），如果在头部插入会移动所有元素（O(N)）。`VecDeque` 解决了这个问题，它的底层是一个环形缓冲区。它的栈上元数据比 `Vec` 复杂（需要记录头尾位置等价信息）。

```text
栈 (Stack)                             堆 (Heap - 环形结构)
+----------------+                   +------+------+------+------+------+------+
| ptr (数据指针) | ----------------> | 数据 | 留空 | 留空 | 留空 | 数据 | 数据 |
+----------------+                   +------+------+------+------+------+------+
| cap (容量)     |                            ^                    ^
+----------------+                            |                    |
| head / tail 指标| (内部细节略微复杂)        尾部追加             头部追加
+----------------+
```

- **底层本质**：堆上的环形缓冲区，支持两端 O(1) 的插入和弹出。
    
- **如何使用**：
    
    ```rust
    use std::collections::VecDeque;
    let mut queue = VecDeque::new();
    queue.push_back(1);
    queue.push_front(2); // 在头部高效插入
    ```

### 9. `bytes::Bytes` / `BytesMut` (网络/IO 专用零拷贝切片)

在处理网络协议时，经常需要对同一块数据包进行切割并分发给不同的协程，用普通的 `Vec` 会导致大量内存拷贝。`bytes` 库通过**引用计数（Reference Counting）**解决了这个问题。

```text
栈 (Stack)                       堆 (Heap - 共享数据块)
+----------------+             +--------------+-----------------------+
| ptr (数据切片) | --------+   | 引用计数(RC) | "HTTP/1.1 200 OK ..." |
+----------------+         |   +--------------+-----------------------+
| len (切片长度) |         +-------------------> | 切片指向的具体片段 |
+----------------+
| data/vtable(元数据)| 
+----------------+
```

- **底层本质**：带有原子引用计数的智能指针切片。你调用 `clone()` 时，它不拷贝底层数据，只是增加堆上的引用计数，并创建一个新的栈上切片视图（指向原始堆数据的不同部分）。
    
- **如何使用**（需要引入 `bytes` crate）：
    
    ```rust
    use bytes::Bytes;
    let b = Bytes::from("hello world");
    // 非常廉价的 O(1) 拷贝，a 和 b 共享堆上的底层数据
    let a = b.slice(0..5); // a = "hello"
    ```
